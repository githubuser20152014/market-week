Before drafting any new Blueprint issue:

1. **Read all previously published issues** in `ContentRepo/wednesday-series/Issues/` — not just the brief in the pipeline. The actual prose sets the voice, establishes what Marcus already knows, and shows what threads are open.
2. **Read the audience persona** at `ContentRepo/wednesday-series/audience-persona.md` — every time. It prevents drift.
3. **Read the article pipeline** at `ContentRepo/wednesday-series/article-pipeline.md` for the current issue's brief and the cross-issue callbacks already planned.

**Why:** The series builds a cumulative mental model for Marcus. Each issue should feel like it picks up where the last one left off — referencing what he did in the previous one-action, using vocabulary already introduced, and resolving threads left open in prior issues.

**How to apply:**
- Explicitly connect to what Marcus learned and did in previous issues (e.g., "Last Wednesday you logged in and found your allocation...")
- Anticipate questions a reader would naturally have carried forward from prior issues (e.g., Issue #1 introduced target-date funds briefly → Issue #2 should clarify how they relate to the two-fund portfolio)
- Callbacks to prior issues should feel earned, not forced — only reference a prior concept when it's genuinely relevant to the current topic
- Terms introduced in earlier issues don't need to be re-defined — Marcus already knows them. Terms introduced for the first time always need a definition.
